# Этап 2. Проектирование интерфейсов взаимодействия

## 2.1 Общая карта сервисов

Все четыре микросервиса выставляют собственные интерфейсы по протоколу HTTP в стиле REST. Сервисы общаются с клиентом и между собой по одной и той же модели. Каждый сервис слушает свой порт и предоставляет свой префикс адресов.

| Сервис | Порт | Префикс адресов |
|---|---|---|
| Пользователи | 8081 | /api/users, /api/profiles |
| Категории | 8082 | /api/categories |
| Операции | 8083 | /api/wallets, /api/transactions, /api/currencies, /api/analytics |
| Отчёты | 8084 | /api/reports |
| Графики | 8001 | /charts |

## 2.2 Общие соглашения

Все ответы и запросы используют формат JSON. Все ответы возвращаются в кодировке UTF-8. Все идентификаторы это глобально уникальные значения формата GUID. Даты передаются в формате ISO 8601. Денежные суммы передаются числом с точностью до сотых.

Аутентификация выполняется через токен. Клиент получает токен после успешного входа и передаёт его в заголовке Authorization при каждом запросе. Токен имеет срок действия двадцать четыре часа.

Для отслеживания запросов используется заголовок X-Correlation-Id. Если клиент не прислал свой идентификатор, сервис создаёт новый и возвращает его в ответе.

Списковые методы поддерживают разбиение результатов на страницы через параметры запроса. По умолчанию возвращается двадцать записей на страницу.

Коды ответов соответствуют общепринятым правилам. Двести значит успешный запрос. Двести один значит создание ресурса. Четыреста значит ошибка в данных запроса. Четыреста один значит отсутствие токена или его недействительность. Четыреста три значит отсутствие прав. Четыреста четыре значит ненайденный ресурс. Пятьсот значит внутренняя ошибка сервиса. Пятьсот три значит временную недоступность зависимости.

Ошибки возвращаются в едином формате, который соответствует стандарту RFC 7807. В теле ответа всегда есть тип ошибки, заголовок, статус, описание и идентификатор корреляции для обращения в поддержку.

## 2.3 Методы сервиса пользователей

Сервис пользователей отвечает за регистрацию, вход и работу с профилями. Регистрация и вход открыты для анонимных запросов, остальные методы требуют токена.

Регистрация создаёт нового пользователя по электронной почте и паролю. Вход проверяет учётные данные и возвращает токен. Метод получения пользователя возвращает все его поля кроме хэша пароля. Методы изменения позволяют сменить почту, пароль и личные данные.

Работа с профилями включает создание профиля, получение списка профилей по пользователю, получение одного профиля, переименование, переключение признака активности и удаление.

Объекты обмена данными в этом сервисе следующие. Запрос на регистрацию содержит почту и пароль. Запрос на вход такой же. Ответ на вход содержит токен и время его истечения. Объект пользователя содержит идентификатор, почту и личные данные. Объект профиля содержит идентификатор, ссылку на пользователя, название и признак активности.

## 2.4 Методы сервиса категорий

Сервис категорий предоставляет работу с системными и пользовательскими категориями.

Доступные методы это получение системных категорий, получение пользовательских категорий по профилю, создание новой пользовательской категории, переименование, смена иконки и удаление. Системные категории недоступны для изменения и удаления.

Объект категории содержит идентификатор, название, тип операции, иконку, признак системной и ссылку на профиль для пользовательских категорий.

## 2.5 Методы сервиса операций

Сервис операций самый объёмный по числу методов. Он работает с кошельками, валютами, операциями и аналитикой.

Методы для кошельков включают создание, получение по идентификатору, получение по профилю, переименование, смену иконки, смену валюты, изменение заметки, смену порядка сортировки и удаление.

Методы для операций включают создание новой операции, получение по идентификатору, получение по кошельку с фильтрами по периоду, изменение описания, смену категории и удаление.

Методы для валют включают получение списка всех валют и принудительное обновление курсов.

Аналитика возвращает агрегированные данные. Метод по месяцам возвращает доходы, расходы и итог за каждый месяц года. Метод по категориям возвращает суммы расходов в разрезе категорий за период.

Объект кошелька содержит идентификатор, ссылку на профиль, название, валюту, начальный баланс, иконку, заметку, порядок сортировки и признак архивности.

Объект операции содержит идентификатор, ссылку на кошелёк, необязательную ссылку на кошелёк назначения для переводов, необязательную ссылку на категорию, тип, сумму, дату и описание.

Объект валюты содержит идентификатор, код, название, номинал и текущий курс.

## 2.6 Методы сервиса отчётов

Сервис отчётов работает по асинхронной модели. Клиент отправляет заявку на отчёт и получает её идентификатор. Затем периодически проверяет статус. Когда отчёт готов, клиент получает ссылку на скачивание.

Доступные методы это создание заявки на отчёт по операциям профиля, создание заявки на отчёт по разбиению расходов по категориям, получение состояния заявки по идентификатору и получение ссылки на скачивание готового файла. Также есть отдельный метод для непосредственной отдачи файла по его ключу.

Заявка содержит идентификатор, тип отчёта, текущий статус, параметры в виде строки, ключ файла после завершения, время создания и время завершения. При ошибке заявка содержит также описание причины сбоя.

## 2.7 Документация API в формате OpenAPI

Каждый сервис автоматически генерирует описание своего интерфейса в формате OpenAPI версии 3. Описание доступно по адресу /openapi/v1.json. Также каждый сервис предоставляет интерактивный обозреватель документации по адресу /scalar. Это полезно для ручной проверки методов и просмотра примеров запросов и ответов.

## 2.8 Диаграммы последовательности

Для четырёх ключевых сценариев построены диаграммы последовательности. Они показывают, в каком порядке вызываются методы и какие данные передаются между сервисами.

Первая диаграмма показывает регистрацию и вход. Клиент отправляет данные регистрации, сервис пользователей проверяет уникальность почты, хэширует пароль и сохраняет учётную запись. Затем клиент отправляет вход, сервис проверяет хэш и возвращает токен.

```mermaid
__SEQ_REGLOGIN__
```

Вторая диаграмма показывает создание операции. Это основной сценарий системы с повышенным уровнем надёжности. Сервис операций сначала проверяет существование кошелька в своей базе. Затем обращается к сервису пользователей для проверки профиля. Если операция требует категорию, сервис операций обращается к сервису категорий. Только после всех проверок операция сохраняется и возвращается её идентификатор клиенту.

```mermaid
__SEQ_CREATETX__
```

Третья диаграмма показывает асинхронное построение отчёта. Клиент отправляет заявку, сервис отчётов сохраняет её со статусом ожидания и сразу возвращает идентификатор. Фоновый обработчик берёт заявку, обращается за данными к сервисам пользователей, категорий и операций, строит файл и сохраняет его в хранилище. Клиент периодически проверяет статус заявки и после завершения скачивает файл.

```mermaid
__SEQ_REPORT__
```

Четвёртая диаграмма показывает построение аналитики. Это короткий синхронный сценарий полностью внутри сервиса операций. Сервис делает выборку по базе с группировкой по месяцам и типам операций, после чего возвращает агрегированные данные клиенту.

```mermaid
__SEQ_ANALYTICS__
```

## 2.9 Межсервисные контракты

Кроме методов для клиента сервисы вызывают друг друга. Эти вызовы тоже идут по REST и используют общий формат ошибок, но требуют сервисного токена. Список основных межсервисных вызовов следующий.

Сервис операций обращается к сервису пользователей для проверки существования и владения профилем. Сервис операций обращается к сервису категорий для проверки категории. Сервис отчётов обращается к сервису пользователей для проверки прав, к сервису операций для получения данных и к сервису категорий для получения названий категорий.

Для всех таких вызовов задана политика устойчивости, описанная в четвёртом этапе. Кратко, у каждого вызова есть ограничение по времени, два повтора при сбое и предохранитель, который размыкается при частых ошибках смежного сервиса.
